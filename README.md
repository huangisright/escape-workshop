# 密室工坊 v4｜部署與使用說明

共有兩個程式檔：`Code.gs`（後端）和 `Index.html`（畫面）。部署一次大約需要 15 分鐘，之後老師和學生只要有網址或 QR code 就能用。

---

## 一、第一次部署（約 15 分鐘）

**請用個人 Gmail 帳號，不要用學校帳號。** 學校帳號通常會限制「所有人都能存取」，學生沒有帳號就進不來。

1. 打開 <https://script.google.com>，按「新專案」，把專案名稱改成「密室工坊」。
2. 把左邊 `程式碼.gs` 裡的內容全部刪掉，貼上 `Code.gs` 的全部內容，按儲存。
3. 按左邊「檔案」旁的 ＋ →「HTML」，檔名輸入 **Index**（大寫 I，不要加 .html），把內容換成 `Index.html` 的全部內容，按儲存。
4. 上方的函式選單選 **setup**，按「執行」。
   - 跳出授權時：選你的帳號 →「進階」→「前往 密室工坊（不安全）」→「允許」。這是因為這支程式是你自己寫的、沒有送 Google 審查，不是真的不安全。
   - 執行完，下方「執行紀錄」會顯示 **管理者代碼**（A 開頭的 7 碼），請記下來。
   - 雲端硬碟裡會多出一個「密室工坊」資料夾，資料庫試算表、學生上傳的檔案、匯出檔都在裡面。
5. 右上角「部署」→「新增部署作業」→ 齒輪圖示選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。
6. 用瀏覽器打開這個網址，輸入管理者代碼，就進到管理頁。

忘記管理者代碼：在編輯器選 `showAdminCode` 執行，看執行紀錄。

## 二、之後更新程式（網址不變）

把新版程式貼上、儲存後：「部署」→「管理部署作業」→ 鉛筆圖示 → 版本選「新版本」→「部署」。**不要按「新增部署作業」**，否則會產生新網址，舊的 QR code 就失效了。

> 加了「學生用 Google 登入」這一版開始，後端要連到 Google 確認登入憑證（`UrlFetchApp`），多了一項「連線到外部服務」的權限。更新後先在編輯器選 `showAdminCode` 按「執行」，照畫面重新授權一次，再部署新版本；沒授權的話學生按 Google 登入會出現權限錯誤。

## 二之一、給老師和學生的網址（GitHub Pages）

**請發這個網址：https://huangisright.github.io/escape-workshop/**

直接打開 Apps Script 的 `/exec` 網址時，如果瀏覽器同時登入了好幾個 Google 帳號，Google 會顯示「很抱歉，目前無法開啟這個檔案」。所以畫面另外放在 GitHub Pages（`docs/index.html`），資料照樣存在部署者的 Google 試算表與雲端硬碟，畫面透過 `doPost` API 存取，不帶任何 Google 登入資訊，登入幾個帳號都不影響。

- `docs/index.html` 是由 `Index.html` 產生的，**不要直接改它**。改了 `Index.html` 之後執行 `node tools/build-pages.js`。
- 換了 Apps Script 部署（網址變了）時，改 `pages.config.json` 的 `api`，再執行一次 `node tools/build-pages.js`。
- 更新 Apps Script 程式時，照上面「二」用「管理部署作業 → 新版本」，網址不變，Pages 版就不用動。
- API 只開放畫面會用到的函式（`Code.gs` 的 `API_FUNCTIONS`）；`setup`、`showAdminCode` 不能從網頁呼叫，管理者代碼只會出現在執行紀錄。

## 三、老師團隊出題（現在就能開始）

1. 管理頁 →「代碼」→ 在「新增老師」一行輸入一位 → 建立老師代碼。
2. 按「列印代碼 QR」，把每位老師的代碼或 QR 交給他。
3. 老師掃 QR 或輸入代碼 →「新增一題」→ 依序填完 7 個區塊。全部自動儲存，上方檢核亮綠燈就完成。
   - 老師可以看到其他老師的題目（唯讀），避免撞題。
   - 老師多了「科學依據」和「換皮檢核」兩欄必填。
4. 管理者 →「示範密室與題庫」→ 建立示範密室 →「挑題與排序」→「封面、說明、結局」填好。
5. 「總覽與審核」→ 示範密室的「試玩」先自己走一遍 →「發布」→ 出現遊戲代碼和 QR。
6. 發布後老師再改題目，**不會影響正在玩的版本**；要讓新內容上線，就按「更新發布版本」。

## 三之零、學生用 Google 帳號登入、老師彈性配組（建議做法）

不用印代碼、不用事先分組。學生先各自出題，老師當天再配組，第二天有人缺席也能隨時換組，**題目跟著人走**。

**登入**：沿用「數學探索島」的 Firebase 專案（`giftedmath-island`），只用來確認是哪個 Google 帳號；確認後伺服器給這位學生一個**個人代碼**（S 開頭 6 碼），之後跟其他代碼一樣用。資料仍然存在部署者的試算表，不會寫進探索島。

**老師（管理頁 →「學生與分組」）**

1. 「開放加入」→ 產生 4 個字的**加入碼**和 QR code，按「放大 QR」投影。
2. 學生掃 QR → 用 Google 登入 → 填姓名、學校班級（加入碼已經從 QR 帶進來）。之後再登入就直接進去，不用再填。
3. 學生加入後，**還沒分組也能先出題**，設計者固定是本人，署名改不了。
4. 「新增組別」→ 用每個人旁邊的選單分組。第一個分進一組的人自動當組長，按 ☆ 可以換組長。
5. 換組時題目預設跟著人走（關卡地點一起清掉）；勾「題目留在原組」就留給原組。已送審的組要先「開放修改」才能把題目移進移出。
6. 大家都加入後可以「關閉加入」；已經加入的學生照常登入。

**學生的權限**

| | 組員 | 組長 |
|---|---|---|
| 新增、修改、刪除自己的題目 | ✓ | ✓ |
| 看同組別人的題目 | 唯讀 | 唯讀 |
| 密室資訊（封面、故事頁、結局圖、心智圖、玩法地圖） | 唯讀 | ✓ |
| 題目順序、送審 | | ✓ |
| 試玩整間 | ✓ | ✓ |

**登不進去的學生（備援）**

- 每位學生的首頁上都看得到自己的個人代碼，可以在登入頁直接輸入。
- 老師可以在「學生名單」直接建個人代碼（一行一位：`姓名：學校班級`），列印個人代碼 QR。學生之後若能用 Google 登入，第一次登入時在「老師已經給我個人代碼了」輸入代碼，就會綁到他的帳號。
- 學生換 Google 帳號：在名單按「解除綁定」，他用新帳號登入時輸入個人代碼就能接回原本的題目。
- 名單上可以改姓名（題目署名一起改）；沒有題目的重複帳號可以刪除。

**第一次用之前要確認的事**

- 外校學生是用個人 Gmail 登入 Firebase 專案。Firebase 專案建在學校帳號的組織下，如果 Google 登入畫面出現「只限機構內使用者」之類的錯誤，要到 Google Cloud 主控台把這個專案的 OAuth 同意畫面設成「外部」。
- 用學校或縣網發的教育帳號登入時，網域管理員可能擋第三方登入；擋住的學生就用個人代碼。

舊的「分組代碼」照樣能用（「代碼」分頁），兩種方式可以並存；同一組裡學生登入看到的題目，用分組代碼登入也看得到。**組員名單只算登入後被分進這一組的學生**；分組代碼上以前手打的組員名字不再列入（組長畫面、總覽、密室島都一樣），「代碼」分頁也不再有組員欄，按「儲存」時舊的手打名字會一起清掉。

**老師與管理者也能用 Google 登入**：登入頁「老師登入」按「老師用 Google 帳號登入」，第一次輸入一次自己的老師代碼（管理者輸入管理者代碼）就會綁定，之後按一下就進來。管理頁「代碼」分頁看得到每位老師、管理者綁定的 Google 帳號，換帳號時按「解除綁定」。代碼本身照樣能用，當備援。

## 三之一、示範密室的選用玩法（氣候變遷密室）

這三種玩法來自《氣候變遷密室逃脫・示範密室規劃草案》，只有老師的示範密室可以開，學生密室不受影響。都不開就是一般密室。

| 玩法 | 在哪裡設定 | 玩家看到什麼 |
|---|---|---|
| **終章碎片** | 「示範密室與題庫」→「封面、說明、結局」→ 勾「開啟終章」，寫終章頁；再到「挑題與排序」幫每一格填碎片 | 每解開一題拿到一塊碎片，放在線索簿；主線全解完進入終章，輸入碎片拼成的密碼才算逃脫 |
| **跳過扣時** | 同一頁的「跳過一題扣幾分鐘」（0 = 不能跳過） | 主線題目下方有「跳過這題」，扣時間但照樣拿到碎片；終章不能跳過 |
| **寶庫** | 「挑題與排序」→ 題庫裡按「放進寶庫」 | 逃脫後還有時間，就一題接一題玩寶庫；可以換下一題或結束遊戲 |

幾個規則：

- **碎片跟著位置走**：第 1 格的碎片給第 1 題，不管那一格放的是哪位老師的題目。調整題目順序時碎片不會跟著搬。
- **終章密碼**留白時，就是碎片依序接起來（例如碎片 7、3、1 → 731）；也可以自己填一個密碼。
- **逃脫時間**在解開終章的當下就定下來，包含跳過扣的時間；寶庫做多做少都不影響。時間到時還在寶庫，仍然算逃脫成功。
- 檢核會擋住：開了終章但有題目沒設碎片、沒寫終章頁、寶庫題目有紅燈。
- 「進行中」會顯示終章、寶庫進度和跳過次數；「數據」多了平均逃脫時間、每題跳過次數，寶庫題標成 V1、V2…。

## 三之二、玩法與地圖：自由選題（預設）／一題接一題

在「密室資訊」的「玩法與地圖」卡片切換。**設計者自己選**：學生組在自己的密室資訊裡改，示範密室由管理者在「封面、說明、結局」裡改。改完要重新發布（或「更新發布版本」）才會生效，正在玩的隊伍不受影響。

| 玩法 | 玩家看到什麼 | 適合 |
|---|---|---|
| **自由選題**（預設） | 題目上方有一張地圖，所有題目同時開放，想先解哪題就點哪題；全部過關（解開或跳過）才逃脫，有開終章就進終章 | 各題互不相依，讓小隊分頭進行 |
| **一題接一題** | 解開才看到下一題，順序照題目清單 | 題目之間有先後關係（例如 A 題的鎖盒裡放 B 題的道具） |

**沒設過玩法的密室一律當成自由選題。** 這個預設出現前就發布的版本照舊一題接一題；下次重新發布時才會變成自由選題，所以有先後關係的密室要記得改成「一題接一題」。

自由選題的地圖樣式（卡片裡有即時預覽）：

| 樣式 | 樣子 |
|---|---|
| **小島**（預設） | 海上的小島。還沒去過的島罩著霧，目前這座島外圍有金色虛線，解開的島插上旗子 |
| **拼圖** | 每題一塊拼圖，凸凹對得上。解開一塊就拼上一塊**封面圖**，全部解開就是完整的封面——記得上傳封面圖片；沒有封面圖時解開的塊塗上顏色 |
| **星球** | 星空裡的星球。還沒去過的很暗，解開的會發光、掛上勾勾 |
| **清單** | 一排題號按鈕，最省空間 |

玩家可以按「收起地圖」把地圖收成一行進度，再按一次打開。地圖可以用鍵盤（Tab、Enter）操作。

自由選題的規則：

- **換題會保留進度**：做到第幾步、看過的提示都會留著。提示倒數只算真的停在這題的時間，換走時暫停。
- **答錯冷卻是全隊共用**：答錯後換到別題，照樣要等冷卻結束。
- **解開或跳過的題目不能再開**。解開一題後會自動打開下一個還沒過的題目，玩家也可以馬上換。
- **碎片照位置放**：解開第 3 題就拿到第 3 格的碎片，不管先解哪一題；終章密碼一樣是碎片依位置接起來。
- 「進行中」的進度欄顯示「已過 2 / 5（看第 4 題）」；「數據」的平均解題時間只算停在那一題的時間。
- 時間到時，只請玩家評有打開過的題目。
- HTML 小遊戲換題後再回來，會重新載入（遊戲內的進度不會保留）。

## 三之三、關卡位置（選填，管理者設定）

在校園裡跑關時，可以幫每一題標上要去哪裡玩（例如「圖書館門口」）。**只有管理者能設定**，學生不用填：

| 密室 | 在哪裡設定 |
|---|---|
| 示範密室 | 「示範密室與題庫」→「挑題與排序」，每一題（含寶庫）旁邊的 📍 欄 |
| 學生密室 | 「總覽與審核」→ 那一組卡片上的「📍 關卡位置」 |

玩家看到的：

- 題目標題下面有「📍 地點」；沒填地點的題目就不顯示。
- 畫面上方有「📍 關卡位置」按鈕，打開是全部題目和地點的表，標出已解開、正在這題。
- **一題都沒填，就不會出現按鈕**，畫面跟以前一樣。

改了地點之後，已發布的密室要按「更新發布版本」才會生效，正在玩的隊伍不受影響。

## 三之五、謎題卡：答對才出現的線索、道具列印檔

**答對第 N 步才出現**：一題裡要「先解出第一個答案，再看到第二張圖」時：

1. 第 2 區「解題步驟鏈」在第一步填**中途答案**。
2. 第 3 區把第二張圖（或文字、音檔、小遊戲）的「什麼時候出現」選成「第 1 步答對後才出現」。
3. 玩家一開始只看到其他區塊；在答案欄輸入中途答案答對後，這個區塊才出現，畫面會捲過去並顯示「正確！新的線索出現了」。斷線備援、「用玩家角度看」、匯出的離線 HTML 都一樣。

檢核會擋：設定的步驟沒填中途答案、步驟已刪除、所有區塊都設成答對後才出現。

**道具列印檔**：要老師印出來的圖或文件，在第 6 區「道具與佈置」每個道具旁上傳圖片或 PDF。玩家看不到，只有老師和同組看得到。管理者 →「列印材料清單」可以逐檔下載、下載一組的全部，或「下載全部列印檔」；檔名是「組名-第幾題-道具」。檔案也在雲端硬碟「密室工坊」資料夾裡，檔名含「列印檔」。

- **PDF**、**小的 PNG／JPG**（3 MB 以下、長邊 3508 像素以內）：原檔上傳，不壓縮，線條最清楚。PDF 上限 8 MB。
- **手機照片**：iPhone 的 HEIC、WebP，或太大張的照片，上傳前在瀏覽器裡自動轉成 JPG，長邊縮到 3508 像素（A4 300 dpi），透明的地方補成白色。Safari 直接讀得懂 HEIC；Chrome 讀不懂時會從 jsDelivr 載入 heic2any 來轉（只在選了 HEIC 時才載入，出題時要有網路）。
- **手寫、手繪道具**：建議用 iPad「檔案」App 的「掃描文件」存成 PDF（會自動裁邊、拉正）。多頁的道具掃成同一份 PDF。
- **製作說明**（選填）：每個道具下面可以寫摺法、剪法、特殊材料等掃描檔看不出來的事，例如「對摺兩次，答案在背面」。材料清單和送審檢視會顯示 📝；玩家拿到的資料（遊玩、斷線包、匯出的離線 HTML）都不含製作說明。

## 四之一、斷線與重新整理（離線備援）

**重新整理、分頁被回收、關掉再開**：進度與計時都在伺服器上，重新打開同一個網址會自動接回；用同一個隊名再進來也是接回原本那場，不會開新局、也不會重新計時（隊名相同但成員完全對不上，會請對方換隊名）。已經結束的隊名可以再開新局。

**玩到一半沒網路**：iPad 會改用事先下載好的題目包繼續玩，答錯冷卻、提示、換題都照常，進度存在這台 iPad 上。網路回來後自動回傳成績，畫面上方會出現「已回傳」。

給學生的口訣：

1. **開始前要有網路**：輸入隊名、按「開始挑戰」都要連網。
2. 開始後看畫面頂端的小字，等它變成 **「離線備援已就緒」** 再走出有網路的地方。
3. 沒網路時照常玩，**不要清除瀏覽器資料、不要開無痕視窗、不要換 iPad**。
4. 玩完（出現證書）要走回有網路的地方，**等頂端出現「已回傳」再離開**。

幾件事要知道：

- 只有**一般與自由選題**的密室有離線備援。開了**終章、跳過扣時、寶庫**的密室（示範密室才能開）仍要全程連網，頂端會顯示「這間密室需要全程連網」。
- 題目包裡的答案是加鹽雜湊，不是明文，但學生若刻意研究仍有機會破解簡單的答案；離線時間由 iPad 自己算，伺服器只檢查開始時間、限時等基本合理性。這是為了能離線所做的取捨。
- 離線時，老師的「進行中」畫面看不到那組的最新進度，回傳後才會更新。
- 連著 Wi-Fi 但實際不通時，會等 15 秒才判定為斷線，再切到離線模式。
- 網頁本身（`docs/sw.js`）會被 iPad 快取，之後沒網路也能重新整理打開；第一次打開要有網路。
- **更新程式的順序不拘**：新版畫面搭舊版後端，或新版後端搭舊版畫面，都只是沒有離線備援，不會壞掉。但要有離線備援，兩邊都要更新（後端照「二」重新部署新版本，畫面推上 GitHub）。

## 五、正式上線前一定要做的實機測試

模擬環境已經跑過完整流程（後端 70 項、介面 21 項全部通過），但下面這幾件事只有在真的 Google 環境和學校的 iPad 上才能確認：

1. **iPad 上傳**：用學生的 iPad 拍照上傳、選相簿圖片上傳、上傳一個 GarageBand 匯出的 m4a。
2. **HTML 小遊戲**：上傳一個 HTML，在玩家畫面裡能不能正常玩。
3. **同時使用**：找 6 台 iPad 同時玩示範密室，同時另外幾台在改題目，看儲存速度。
4. **學校網路**：確認學校 Wi-Fi 沒有擋 `script.google.com` 和 `script.googleusercontent.com`。
5. **離線備援（iPad Safari）**：用一台 iPad 玩示範密室，看到「離線備援已就緒」後，打開飛航模式，答幾題、重新整理頁面、玩到出證書；關掉飛航模式，確認頂端出現「已回傳」，管理頁「進行中」「數據」有這一場。**這項只有實機能驗證，自動測試只能在電腦的 Chrome 上模擬。**

以老師團隊的示範密室做這次測試最剛好。如果有任何一項不行，就退回 Holiyo：學生仍然用這個平台交件，檔案已經依組別和題號整理好，你轉傳也會比以前快。

## 六、已知限制

- 每個檔案上限 8 MB；圖片會在 iPad 上自動壓縮到長邊 1400 像素。
- Google 免費帳號的網頁應用程式，同時執行的請求數有上限。系統已經把儲存排隊處理，失敗會自動重試；但如果全部 27 人在同一秒狂按，儲存可能會慢幾秒。
- 匯出的「整間密室離線版」請用**筆電瀏覽器**開啟。iPad 從「檔案」App 直接開 HTML，不一定會執行程式。
- HTML 小遊戲的密碼寫在原始碼裡；營隊現場沒問題，但若要公開給校外玩，建議改成不顯示原始碼的設計。
- 答錯冷卻、提示時間都由伺服器判斷，玩家改不了；答案也不會送到玩家的平板上。
- 匯出的離線版 HTML 只有主線題目，不含終章、跳過和寶庫，一律是一題接一題。
- 離線備援看「四之一」：iPad 在無痕模式、或瀏覽器自己清掉網站資料時，備援可能失效；iOS 偶爾會在記憶體不足時回收分頁，但進度存在 iPad 上，重新打開仍會接回。

## 七、自動測試（改程式的人才需要）

`tests/` 裡用模擬的 Google 服務（試算表、雲端硬碟等）在電腦上跑 `Code.gs`，不用部署：

```
node --test tests/backend.test.js tests/climate.test.js tests/free.test.js tests/api.test.js tests/autosave.test.js tests/offline.test.js tests/places.test.js tests/students.test.js tests/reveal-print.test.js tests/islands.test.js   # 後端（islands 另含展示頁的瀏覽器測試）
node --test tests/ui.test.js tests/offline-ui.test.js tests/pages-offline.test.js tests/students-ui.test.js tests/reveal-print-ui.test.js tests/print-photo-ui.test.js   # 介面（需要 Playwright 與 Chromium）
node tests/bench.js                                                 # 量每個動作碰試算表幾次、讀多少資料（越少越快）
```

- `backend.test.js`：v4 原有的流程（代碼、謎題卡檢核、送審、上傳、發布凍結、遊玩、數據、匯出）。
- `climate.test.js`：終章碎片、跳過扣時、寶庫，以及舊版快照仍可遊玩。
- `free.test.js`：自由選題（預設值、設計者可改、換題保留進度、提示計時、碎片照位置、冷卻共用、舊快照相容）。
- `ui.test.js`：在瀏覽器裡走一遍管理者設定 → 發布 → 玩家從頭玩到評分。
- `offline.test.js`：同隊名接回、題目包雜湊、離線回傳的檢查。
- `offline-ui.test.js`：連線玩 → 斷線繼續玩 → 重新整理 → 逃脫 → 連線後自動回傳。
- `pages-offline.test.js`：用 GitHub Pages 版（真的 fetch、真的 service worker）測整台斷網與「連著 Wi-Fi 但不通」。
- `students.test.js`：Google 登入驗證（含假憑證、Firebase 不通時改走 Google 憑證）、加入碼、個人代碼綁定、未分組出題、組長權限、換組時題目跟著人走、送審過的組。
- `islands.test.js`：密室島只列已發布的學生密室、不洩漏答案、數據不含試玩、發布／下架即時更新；展示頁切換與隱藏名字。
- `students-ui.test.js`：在瀏覽器裡走一遍學生 Google 登入加入 → 出題 → 老師配組、換組長、換組 → 學生看到自己的組；組員唯讀。

模擬環境測不到的事（iPad 上傳、學校網路、多台同時使用）仍然要照第五節實機測試。
